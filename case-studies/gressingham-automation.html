Case Study — Automation

Gressingham Foods Automation Toolkit

Gressingham Foods, January 2026 – Present

Problem

A food production environment with legacy tooling (tkinter-based internal apps) and manual, error-prone compliance processes — including UK Extended Producer Responsibility (EPR) packaging classification and shelf-life data management — running on locked-down hardware with no cloud access.

Approach

  • Built and deployed a fully local, CPU-only LLM-based OCR pipeline using llama.cpp, running on locked-down hardware with no GPU and no external network access
  • Automated shelf-life data merging, PDF classification, and Outlook-based reminders for compliance deadlines
  • Split multi-page calibration certificate PDFs by instrument serial number and fed the due dates into reminders
  • Started moving the tools from tkinter desktop apps to a Flask web app

Outcome

Manual document handling became a set of tools the quality team uses daily, alongside FoodOps/QualityApp administration (conditional expressions and live data-source fixes). This work led directly to KVACK, an AI assistant for the same documents.

The hardest constraint: getting an LLM pipeline running entirely offline, on locked-down office PCs with no GPU and no admin rights.
